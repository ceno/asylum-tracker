# Asylum Tracker

A mobile-first daily checklist for the mobile game **Last Asylum: Plague**. It's for free-to-play players who want the most progress for the least time in game. It is styled after the game's own event screens: a navy page with pale steel panels, gold titles with a dark outline, and game art for every item (item icons on tiles coloured by rarity, building renders, hero art). The header holds a button for each Duel day (its icon, numeral and weekday). It slides away while scrolling down and comes back on scrolling up. The Alliance Duel card sits at the top. On the server's last day of a week (Sunday) or month, a "Last chance to buy" card above it lists the shops that reset after that day: the Alliance, VIP, Expedition and Sanctuary Shops weekly and the Honor Shop monthly. For the current Duel day (Days 1–6 plus a rest day) it shows a banner in the day's colour with its art and the time to the reset, the day's objectives as tiles (three to a row) under "Anytime", then the next scoring day's objectives under "Save for tomorrow". On Day 6 that skips the rest day and shows Day 1. Objectives that also score in Survival Battle (its 4-hour rounds are counted from the reset) are taken out of the "Anytime" list and shown on a timeline at the times their round runs that day, with the current round marked. The timeline has a dot at each round's start; a round's end only gets its own smaller dot when no round starts then. The timeline only shows rounds between 8am and midnight (`SURVIVAL_BATTLE.show`). An objective whose rounds all fall outside that stays under "Anytime". On the rest day there are no Duel objectives, so it shows every Survival Battle round in those hours instead. Below it are the daily routine cards (Morning, Midday, Evening). These and the "Last chance to buy" card fold down to their header once every item is ticked. Each task has its icon and a circle that fills with a green check. Then come a "prep for tomorrow" list and a weekly saving cheat sheet. It is a static site served by GitHub Pages from the repo root. There is no build step, no framework and no dependencies; the fonts are served from the repo too. Ticks are stored in `localStorage` for each game day, so they reset at the in-game daily reset. The user can set the reset time and the weekday Duel Day 1 falls on in the ⚙ settings.

## Files

- `data.js`: all content (`ROUTINE`, `LAST_CHANCE`, `DUEL_DAYS`, `SURVIVAL_BATTLE`, `PREP`, `CHEATSHEET`, `ICON_RARITY`). Most edits belong here. Every task, shop, objective, prep item and cheat-sheet row has an `icon`, each routine block and Duel day an `art`, and each Duel day an `icon` for its button. They name a file in `assets/` without `.webp`. The prefix says how it's drawn: `i-` an item on a tile coloured by `ICON_RARITY` (blue unless listed), `b-` a building as is, `h-` hero art and `art-` a scene, both cropped on the Duel banner. A routine task with `notSunday: true` is hidden on the server's Sunday. An objective written as `{ text, sb }` scores in the Survival Battle rounds with theme `sb`. `SURVIVAL_BATTLE.schedule` is the weekly round order copied from the in-game calendar, keyed by Duel day (7 is the rest day). The game numbers the two events out of sync: Survival Battle's Day 1 is the Duel rest day, so its Day N is Duel Day N-1. Convert its day numbers before copying a schedule in. The Duel values come from https://last-asylum-plague.fandom.com/wiki/Alliance_Duell_Guide. WebFetch gets a 402 from Fandom, so read the page through the API instead: `curl -sL "https://last-asylum-plague.fandom.com/api.php?action=parse&page=Alliance_Duell_Guide&prop=wikitext&format=json&formatversion=2"`.
- `app.js`: rendering, game-day maths and storage. Tick keys look like `routine:<block>:<id>`, `last-chance:<id>` and `prep:<day>:<n>`, grouped under a `YYYY-MM-DD` game date. Shop weeks and months go by the server's date, which is the UTC date in the middle of the game day. West of UTC that is a day after the local game date. Changing an item's `id` drops its saved tick. It also asks for persistent storage and shows a storage readout in ⚙. That readout shows whether the page is running as a Home Screen app, whether storage is protected, and the `created` time of the saved data (it jumps forward if the data was wiped). Each time the app comes back into view, it compares the deployed files in `APP_FILES` with the ones it started with and reloads if they differ. Add any new script or stylesheet the page loads to `APP_FILES`. Images and fonts are left out, so the check stays light: give a changed image a new file name, which changes `data.js` too.
- `sw.js`: network-first service worker. Every load revalidates with the server instead of reusing GitHub Pages' 10-minute cache, and the cache is only used offline. Without it, the update check above can't tell what's running.
- `index.html`, `style.css`: markup and styles. Colours are CSS custom properties on `:root`. There is one look (light panels on a dark page), not a light and a dark mode; the settings card sets `color-scheme: light` so its form controls stay readable.
- `assets/`: the game art as small `.webp` files, and `assets/fonts/` with Lilita One and Nunito (Latin, under the SIL Open Font License, whose texts are beside them). The art came from fan projects on GitHub that took it from the game: item, chest and skill icons from `klingo/last-asylum-plague`, building renders and hero art from `Fongobongo/last-asylum-website`. Those are small copies. `assets/library/` keeps every game image found (about 500: items, chests, raven items, lord skills, event banners, buildings, heroes, monsters) at full size for future use; the page loads nothing from it. Browse it at `assets/library/index.html`, and see its `README.md` for where each folder came from and how to bring an image into the page (resize it into `assets/`, about 128px for items or 220px for buildings, then name it in `data.js`).

The storage key is still `asylum-routine:v1` from before the rename. Keep it so saved ticks aren't lost.

## Commands

```bash
# Serve locally (then open http://127.0.0.1:8765/, e.g. via VS Code "Simple Browser: Show")
python3 -m http.server 8765 --bind 127.0.0.1

# Smoke test in a mobile browser with the playwright-cli skill
playwright-cli open --mobile http://127.0.0.1:8765/
playwright-cli console          # should show no errors
playwright-cli close && rm -rf .playwright-cli
```

Deploy: push to `main`. GitHub Pages is set to deploy from the branch, from the `main` root. Live site: https://ceno.github.io/asylum-tracker/

## Preview artifact

There is a private claude.ai artifact of the page at https://claude.ai/artifact/A8tFVv6s1ZnXcVVceQdeFL so changes can be previewed in claude.ai before merging. After any change to the page, republish it to that same URL with the Artifact tool:

- `url`: the URL above. If this session hasn't published it yet, first read it with `action: "read"` and also with `paths: ["style.css", "data.js", "app.js"]`, otherwise the publish is refused for overwriting files it hasn't read
- `file_path`: `index.html`
- `files`: a list of `style.css`, `data.js`, `app.js` and every file under `assets/` (`[{"path": "style.css"}, …, {"path": "assets/i-stamina.webp"}, …]`), so the images and fonts are published beside the page. Before the first publish in a session, also list the artifact's files with `action: "list", scope: "files"`, so the publish may replace the ones already there

Never publish without `url`. That creates a second artifact instead of updating this one. Ticks saved in the artifact are separate from the live site's. `sw.js` is left out on purpose: the preview runs without a service worker, so it never reloads itself.
